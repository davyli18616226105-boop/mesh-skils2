# Mesh 四源报价

版本：1.0.0。与 mesh-standard-quotation 独立，不修改其模板或流程。

## 固定交付与边界

- 接收产品需求 → 四源最新检索 → 确认关键规格 → 三维报价数据 → 公式与范围校验 → 独立在线飞书表格 → 交付。
- 报价主表使用九列：产品线、服务项、必选/可选、功能清单、单价（元）、数量、单位、折扣、折后价（元）。按产品、实施、运维顺序分区，各区小计及总价始终保留。
- 复刻图片的蓝色标题/表头、黄色小计/总价、换行、细边框及分组布局，不复用图片价格、200账号、40人天、折扣、维保比例或水印。
- 资料没有实施或运维内容时保留区块，相关字段真空；未知不等于0、免费、已含或不适用。不能只输出聊天价格或把截图贴进表格。
- 只读取四源及为理解其本体所需的嵌入表/同步块。不得未经授权扩展至全公司、其他客户历史报价或公开网站取价。
- 刊例是内部资料。输出默认供当前用户内部审阅，不公开分享，不自动发送客户，不把内部折扣门槛、底价、成本、人员信息或来源链接灌入对客主表；对客前另行确认可披露范围与授权。

## 1. 每次运行先读取依赖和资料

1. 表格任务第一工具调用读取当前环境 sheet/SKILL.md；按其引擎、公式、格式和导入要求操作。飞书链接不得浏览器打开。
2. 完整读 [四源配置与检索](references/sources.md)、[字段与计价契约](references/quote-contract.md)。使用脚本前Read实际脚本。
3. 本轮是新技能运行或新报价时重新读取四源当前版本，不能把技能里的来源标题、历史快照或旧价格当实时事实。
4. 先用 lark-drive/SKILL.md 及 inspect 参考解析 sources.json 中四个原始 wiki。按类型路由：sheet → sheet，docx → lark-doc，其他类型 → 对应技能。完整保留返回和来源映射，原始wiki URL不丢。
5. 源表列出真实子表，读取所需完整产品/模式范围，确认complete与实际行列。源文档先读目录再读相关产品、价格、部署、服务及限制章节，不能仅靠标题或摘要。
6. 文档里的sheet/synced_reference不是已读正文。读取与当前产品有关的嵌入价目及同步区间，并读取对应评论。仅引用指定同步块，不将已废弃同步源整份当现行刊例。权限失败不绕过、不把无权限当无价。
7. 对给定四源本体查读属于明确对象操作，走上述技能；只有用户另外明确需要跨来源背景/更广检索时，完整读doubao-enterprise-search及适用参考后，单独调用企业搜索。搜索候选仍须回到真实来源核验，不能越过四源限定补价。

## 2. 产品匹配与必要确认

- 记录产品/模块、功能范围、版本、SaaS/私部订阅/买断、购买周期、直客/分销、地区、数量、账户或席位、场景、数据/算力需求，以及实施、运维等级与期限。
- 仅输入产品名称时，允许先查四源目录形成真实候选；同名多产品、部署或周期差异会改变价格时，用interaction_ask先确认，不取首条、不替用户选版本。
- 核心产品唯一后，数量、折扣、周期或服务范围未明确的，可先交完整草稿并留空，不能为补齐总价自行假设1套、1年或标准实施人天。必选与最低购买量分别呈现；客户实际数量仍需确认。
- 实施按资料中的交付内容、服务包或人天取价；不能用产品价格反推实施单价，不将参考15人天或图片40人天当项目工作量。
- 运维区分首年标准已含、非标准另收费、续年费率、License/产品/总合同基数与期限。比例区间不擅取端点；免费资料必须适用于当前SKU、部署和服务等级。
- 不继承其他技术方案中的禁止外联或部署决策为新客户条件；本次客户条件与产品销售限制冲突时先确认，不改写产品能力。

## 3. 证据、冲突与价格状态

- 按产品线+模块+规格+部署+周期+地区/渠道+有效价格版本匹配。源字段、单位、合并区、批注和完整上下文一起核验。
- 区分现行刊例、标准参考报价、历史示例、仅最低折扣、已经折后价。读取日期/更新日期不等于生效日；标题“生效中”需与正文及限制一致。
- 不预设四源序号优先级。只有明确适用关系或替代/审批依据才能解决差异；同SKU同周期冲突保留记录，该金额不进入正式报价。
- 维护内部证据：source_id、原始wiki、实际返回URL、revision/读取时间、子表/章节/单元格、原句、商品身份、价格状态及适用条件。每个填入数值或服务规则均有证据或客户本轮确认。
- Source2订阅文档额度、SaaS打标年/月、已废弃同步源、Source1订阅段买断字样、Source3月费与年计费项、积分/Token共享code、Source4分项折扣与总则等属于需复核情形，不能按便宜者选价。
- 套餐已含模块/席位/实施不重复收费；资源包额度与购买包数分开；积分与Token备选按适用条件择一，不因code相同合并两种计量。
- 缺失、冲突、不确定价格、单位或折扣以unknown留空；资料有价格但生效/适用或授权未确认的可披露为内部参考，不形成正式总价。

## 4. 构建可编辑报价表

1. 按quote-contract形成内部JSON，输入仅包含真实选定行，未选可选项单独留空。公有模型、云资源等若需另购归入产品区注明类别，勿并入License。
2. 以assets/quote-input-template.json为输入骨架，执行scripts/build_quote.py生成新.xlsx；脚本只确定性校验、计算和复刻布局，不负责事实检索、不自动发送或上传。默认生成空缺完整草稿。
3. 库存模板assets/quotation-template.xlsx及assets/sources.json中的在线空白模板不含商品示例价格。每次新报价生成独立文件/工作簿，不改源库或模板，不复用上个客户表。客户明确修改既有报价时先回读最新表，按sheet最小改动，不从零覆盖。
4. 单价、数量、折扣和周期作为数值输入；派生行额、小计和总价使用实际单元格公式。参数缺失不计算，空折扣不等于1；已经折后单价不再次打折。
5. 三维小计仅在该维度完整时出数；某维度unknown则小计空。所有关键商务条件和三维完整后才显示正式总价。已确认部分可在表底单列“已确认金额小计（非最终报价）”，不得冒作总价。
6. 本地.xlsx作为中间资产，用sheet的+workbook-import导入并按ready/job_status及data.extra处理兼容性。若选在线模板原生复制，完整读取模板并用drive +copy，仅写新副本，保留格式。
7. 布局需要扩行时维护合并范围、状态/计量输入、行金额和汇总引用；主区只九列，非敏感商务待确认项在表底。内部原文与审批证据独立保存，不以隐藏Sheet当信息隔离。

## 5. 验收与交付

- 校验四源相关范围已检查、产品与条件唯一、三维/九列完整、没有图片金额污染、原价/折后/费率不混用、包内不双收、未知没有变0、公式与独立复算一致、文字换行完整。
- 发布正式总价前确认币种、含税口径、税率适用性、期限、有效期、数量、价格生效、折扣授权与依赖。脚本校验只能证明填写/计算逻辑，不能证明商业批准或交付可行性。
- 只交付本次真实创建、完成写入且可访问的在线表格，用present_files交付，处理部分成功而不重复创建。写入结果未知先查证。
- 窗口回复1—2句说明产品、三维结构、草稿/正式状态及主要缺口；不要把每个内部报价依据外发。只建技能时交完整技能目录，说明尚未执行实际客户报价或公开发布。
